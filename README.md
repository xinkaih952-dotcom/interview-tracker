# 面试进度管理

一个面向 HR 的轻量级面试进度管理工具。用看板集中管理候选人所处的面试阶段，记录每轮面试评价，自动提醒停滞的候选人，并实时统计通过率和招聘周期。

**在线访问：** https://xinkaih952-dotcom.github.io/interview-tracker/

## 解决的问题

同时跟进多个岗位、几十位候选人时，面试进度通常散落在表格、聊天记录和邮件中，容易出现以下问题：

- 难以快速了解每位候选人处于哪个阶段，长时间没有推进的候选人容易被遗漏
- 不同岗位的面试轮次不同，容易安排错轮次
- 面试官的评价分散在各处，决策时难以集中查看
- 需要汇报招聘进展时，要手动统计人数、通过率和招聘周期
- 每次约面试都要重新编写邀请文案

本工具把候选人信息、面试阶段、评价和统计数据集中在一个页面，打开即可掌握整体进展。

## 功能

| 功能 | 说明 |
|---|---|
| 候选人档案 | 记录姓名、联系方式、应聘岗位、来源渠道、备注，支持新增、查看、编辑、删除 |
| 进度看板 | 按待约面、一面、二面、终面、Offer、淘汰六个阶段分列展示；点击卡片即可切换阶段 |
| 岗位流程模板 | 为每个岗位设置需要的面试轮次（如行政文员只有一面和终面），切换阶段时只显示该岗位的轮次 |
| 超时提醒 | 卡片显示在当前阶段的停留天数，超过 7 天标黄、超过 14 天标红；Offer 和淘汰不提醒 |
| 面试评价 | 按轮次记录面试官、评分（1–5 分）和评语；卡片显示最近一轮的评分 |
| 面试邀请文案 | 一键生成正式的面试邀请，自动填入姓名、岗位、轮次，可填写时间、地点、面试官和公司名称，一键复制 |
| 统计条 | 页面顶部实时显示各阶段人数、各岗位通过率、平均招聘周期和平均淘汰周期 |
| 导出 CSV | 导出候选人明细、面试评价明细、各阶段人数、各岗位通过率和招聘周期，可直接用 Excel 打开 |
| 示例数据 | 一键载入 15 位虚构候选人及对应的流程模板和面试评价，便于快速体验全部功能 |

## 统计口径

### 通过率

```
通过率 = Offer 人数 ÷（Offer 人数 + 淘汰人数）
```

只统计**已有结论**的候选人，仍在面试流程中的候选人不计入分母。

**为什么这样计算：** 假设某岗位共 10 人，其中 5 人尚未面试、3 人淘汰、2 人获得 Offer。

- 若按总人数计算：2 ÷ 10 = 20%
- 按本工具的口径计算：2 ÷ (2 + 3) = 40%

前一种算法会让招聘刚开始的岗位通过率明显偏低，无法反映真实的筛选结果。本工具的口径只看已有结论的候选人，不同进度的岗位之间也能比较。

某岗位还没有候选人得出结论（分母为 0）时，显示"暂无数据"，而不是 0%。

### 招聘周期与淘汰周期

```
平均招聘周期 = 已获 Offer 的候选人，从首次录入到进入 Offer 阶段的平均天数
平均淘汰周期 = 已淘汰的候选人，从首次录入到进入淘汰阶段的平均天数
```

每位候选人记录两个时间，含义不同：

- **首次录入时间**：候选人第一次加入系统的时间，之后不再改变
- **进入当前阶段时间**：每次切换阶段时更新，用于超时提醒和周期计算

某一类还没有候选人时，显示"暂无数据"。

### 超时提醒

- 停留天数 = 当前时间 − 进入当前阶段的时间，只有切换阶段时才重新计时，修改其他信息不影响
- 超过 7 天标黄，超过 14 天标红
- Offer 和淘汰已有结论，不显示停留天数，也不提醒

## 技术说明

- **纯前端实现**：使用原生 HTML、CSS、JavaScript，无框架、无构建步骤，部署在 GitHub Pages
- **本地存储**：候选人、流程模板、邀请中的公司名称分别保存在浏览器的 localStorage 中，不上传到任何服务器
- **CSV 导出**：文件带 UTF-8 BOM，Excel 打开中文不乱码；以 `=`、`+`、`-`、`@` 开头的内容会自动转义，防止被 Excel 当作公式执行
- **安全渲染**：用户输入的内容以纯文本方式显示，防止脚本注入
- **剪贴板兼容**：优先使用 Clipboard API 复制，不支持时自动改用传统复制方式

### 使用限制

由于数据只保存在当前浏览器中：

- 更换电脑、更换浏览器或清除浏览器数据后，数据将无法找回
- 数据无法在多人之间共享，面试官也无法自行填写评价

因此本项目定位为个人使用和功能演示。如需团队协作，需要增加后端服务和数据库。

## 本地运行

无需安装任何依赖，下载仓库后直接用浏览器打开 `index.html` 即可。
