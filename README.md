# 面试进度管理

一个面向 HR 的轻量级面试进度管理工具，用看板集中管理候选人所处的面试阶段，并实时统计各阶段人数和各岗位通过率。

**在线访问：** https://xinkaih952-dotcom.github.io/interview-tracker/

## 解决的问题

同时跟进多个岗位、几十位候选人时，面试进度通常散落在表格、聊天记录和邮件中，容易出现以下问题：

- 难以快速了解每位候选人处于哪个阶段，容易漏约、漏跟进
- 需要汇报招聘进展时，要手动统计各阶段人数和通过情况
- 各岗位的招聘效果缺少统一口径，无法直接比较

本工具把候选人信息、面试阶段和统计数据集中在一个页面，打开即可掌握整体进展。

## 功能

| 功能 | 说明 |
|---|---|
| 候选人档案 | 记录姓名、联系方式、应聘岗位、来源渠道、备注，支持新增、查看、编辑、删除 |
| 进度看板 | 按待约面、一面、二面、终面、Offer、淘汰六个阶段分列展示；点击卡片即可切换阶段 |
| 统计条 | 页面顶部实时显示各阶段人数和各岗位通过率 |
| 导出 CSV | 一键导出候选人明细、各阶段人数和各岗位通过率，可直接用 Excel 打开 |
| 示例数据 | 一键载入 15 位虚构候选人，便于快速体验全部功能 |

## 通过率计算方式

```
通过率 = Offer 人数 ÷（Offer 人数 + 淘汰人数）
```

只统计**已有结论**的候选人，仍在面试流程中的候选人不计入分母。

**为什么这样计算：** 假设某岗位共 10 人，其中 5 人尚未面试、3 人淘汰、2 人获得 Offer。

- 若按总人数计算：2 ÷ 10 = 20%
- 按本工具的口径计算：2 ÷ (2 + 3) = 40%

前一种算法会让招聘刚开始的岗位通过率明显偏低，无法反映真实的筛选结果。本工具的口径只看已有结论的候选人，不同进度的岗位之间也能比较。

某岗位还没有候选人得出结论（分母为 0）时，通过率显示为"暂无数据"，而不是 0%。

## 技术说明

- **纯前端实现**：使用原生 HTML、CSS、JavaScript，无框架、无构建步骤，部署在 GitHub Pages
- **本地存储**：数据保存在浏览器的 localStorage 中，不上传到任何服务器
- **CSV 导出**：文件带 UTF-8 BOM，Excel 打开中文不乱码；以 `=`、`+`、`-`、`@` 开头的内容会自动转义，防止被 Excel 当作公式执行
- **安全渲染**：用户输入的内容以纯文本方式显示，防止脚本注入

### 使用限制

由于数据只保存在当前浏览器中：

- 更换电脑、更换浏览器或清除浏览器数据后，数据将无法找回
- 数据无法在多人之间共享

因此本项目定位为个人使用和功能演示。如需团队协作，需要增加后端服务和数据库。

## 本地运行

无需安装任何依赖，下载仓库后直接用浏览器打开 `index.html` 即可。
